### Q1. Critical quotient for the P2 forcing relation

Let `Q = H*/C88` be the quotient obtained by contracting the 88 prescribed equality conditions, and let `p` and `q` denote the quotient vertices containing original vertices 217 and 490.

The checked quotient has 305 vertices and 1599 edges. `Q` is 5-colorable, while

`G = Q + pq`

is not 5-colorable. Moreover, deleting any one vertex from `G` makes it 5-colorable. Thus the added-edge obstruction is vertex-critical at the checked quotient level. `G` has no articulation point and no 2-vertex cut, and the `p`-to-`q` vertex connectivity in `Q` is 6.

Evidence: [`results/quotient-critical/analysis.json`](results/quotient-critical/analysis.json), generated by [`tools/quotient_critical.py`](tools/quotient_critical.py). The SAT checks include `G` UNSAT and all 305 single-vertex deletions SAT.

### Q2. One local common-neighborhood forcing lemma

A general 5-coloring rule is:

> If the common-neighborhood graph of vertices `u,v` is not 3-colorable, then every proper 5-coloring has `c(u)=c(v)`.

Reason: if `u,v` had distinct colors, every common neighbor would have only the remaining three colors available.

In the checked quotient, the port vertex `p` (containing 217) and qnode 22 (original vertex 36) have a common neighborhood consisting exactly of a `K4`, so they are forced equal by this local rule. This rule does **not** connect `p` to `q`; it is a genuine local lemma but not a complete explanation of P2 forcing.

Evidence: [`results/local-equality-chain/analysis.json`](results/local-equality-chain/analysis.json), generated by [`tools/local_equality_chain.py`](tools/local_equality_chain.py).

### Q3. Six-vertex color-symmetric separator interface

This is currently the shortest structural explanation found for the P2 same-color forcing in `Q`.

A minimum `p`-`q` vertex separator is

`S = {0, 6, 8, 9, 10, 266}`

in quotient-node numbering. In original-vertex components these six boundary nodes are:

- `q0   = {0,324,376}`
- `q6   = {8,18,364}`
- `q8   = {10,12,54}`
- `q9   = {11,55,288}`
- `q10  = {19}`
- `q266 = {375,394}`

Deleting `S` separates the quotient into a 261-vertex component containing `p` and a 38-vertex component containing `q`.

There are 202 canonical color partitions of six labeled boundary vertices using at most five colors. The discovery computation (CaDiCaL195) found that only one boundary partition extends to both sides. An independent implementation using Glucose4 verified the complete side tables:

- left / `p` side extendable states: 2;
- right / `q` side extendable states: 81;
- intersection: exactly one state, `012203`.

The restricted-growth string `012203` encodes only equality classes, not color names. Its blocks are

`{q0,q10} | {q6} | {q8,q9} | {q266}`.

For this unique common state, both side solvers force their port to the same singleton boundary color, namely the block containing `q6`. Hence every proper 5-coloring of `Q` satisfies

`c(217) = c(490)`.

This is a **color-symmetric six-vertex interface proof** of the conditional P2 forcing statement. It is not by itself an unconditional unit-distance gadget and therefore does not prove `χ(R²) >= 6`.

Discovery evidence: [`results/separator-interface/analysis.json`](results/separator-interface/analysis.json), generated by [`tools/separator_interface.py`](tools/separator_interface.py).

Independent verification: [`results/separator-verify/analysis.json`](results/separator-verify/analysis.json), generated by the separate Glucose4 verification workflow. The verifier explicitly enumerates all 202 canonical boundary states on each side and checks that their intersection is exactly `{012203}`.

### Structural non-results worth retaining

The direct common neighborhood of the P2 ports 217 and 490 is empty, so the forcing is not explained by the simplest `4-chromatic common neighborhood => same fifth color` argument. The critical graph `Q + pq` also has no articulation point or 2-vertex cut. These negative structural facts motivate the six-vertex interface rather than a smaller two-piece decomposition.

Exact port-relation scanning also found 20 quotient vertices that are forced to have the same color as `p`; see [`results/port-relation-scan/analysis.json`](results/port-relation-scan/analysis.json). This is useful structural data, but Q3 is presently the cleaner proof-level summary.

## Search method

`tools/semantic_cegis_portfree.py` runs an exact master/oracle CEGIS loop.

The master selects four non-port vertices. Every known A/B fooling pair induces a difference graph on the non-port vertices; the selected four-set must contain at least one edge of every such difference graph. Equivalently, it may not be an independent four-set in any accumulated difference graph.

The oracle asks for an `A` coloring and a `B` coloring with the same complete equality pattern on the proposed four-set. SAT produces another sound fooling-pair cut. UNSAT produces a genuine semantic-interface candidate. If the master itself becomes UNSAT, all port-free equality interfaces of support at most four are excluded.

## Reliability and timeouts

The workflow uses a pinned upstream commit, validates every seed coloring, writes checkpoints atomically, and treats timeout/UNKNOWN states as **non-results**. A timeout is never converted into SAT or UNSAT evidence.

Run 2 showed why the guard is necessary: one solver call remained active for several minutes after the last completed CEGIS iteration. The outer timeout safely stopped it without losing the previous checkpoint. Before another large continuation run, the preferred engineering improvement is a sound per-query interruption/UNKNOWN path or a specialized fast four-set candidate generator, while retaining exact SAT for certificate-producing decisions.
