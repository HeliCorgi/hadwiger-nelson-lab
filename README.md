### P1. Checked UNSAT proof for the P2 contradiction

Normalize the contradiction as

`COMMON ∧ A-only ∧ B-only`,

where the common part is the shared 5-coloring encoding of `H*`, `A-only` contains the C88 equality constraints, and `B-only` contains `c(217) != c(490)`.

The normalized CNF has:

- 1965 Boolean variables;
- 12,318 common clauses;
- 880 A-only clauses;
- 5 B-only clauses;
- 13,203 clauses total.

Glucose4 produced an UNSAT DRUP proof. The proof was independently processed by pinned `drat-trim` commit `2e3b2dc0ecf938addbd779d42877b6ed69d9a985`, converted to LRAT, and the LRAT file was accepted by the independent `lrat-check` checker.

The trimmed LRAT dependency cone uses 11,018 initial clauses and 215,041 learned clauses. All 880 A-only clauses and all 5 B-only clauses remain in the cone; all 393 graph vertices occur in its initial support. Thus raw proof trimming alone does not reveal a small local cause of the P2 contradiction.

### P2. Proof-guided color-symmetric interpolation probe

Learned clauses in the original proof were mined for 4-, 5-, and 6-vertex supports. For each selected support, both sides were projected to canonical equality partitions, eliminating color names. 180 candidates of each size were checked exactly, 540 total.

No sampled support separated A from B: separator count 0 for sizes 4, 5, and 6. In each size class the smallest A/B state overlap was 1, so several proof-guided supports are one equality-partition state away from separation. This is a search result, not a completeness theorem.

Evidence: [`results/proof-interpolant-deep/DEEP_SUMMARY.json`](results/proof-interpolant-deep/DEEP_SUMMARY.json), generated by [`tools/proof_interpolant_deep.py`](tools/proof_interpolant_deep.py).

### Interpretation

The checked LRAT certificate establishes the SAT-level contradiction rigorously, but its dependency cone remains global. The more promising route to a human-readable color-symmetric statement is therefore to extract a small semantic boundary/interface and certify its finite state table, rather than expecting ordinary UNSAT-core trimming to expose a tiny graph sublemma automatically.

- `A = H* ∧ C88`, where `H*` is the first minimal edge core and `C88` is the 88-condition P2 forcing set;

For a set `S` of non-port vertices, the observable is the equality partition induced on `S` by a proper 5-coloring. The search asks whether some four-set `S` separates the projected model sets of `A` and `B`.

Searching exactly four vertices is complete for support `<= 4`: a separating equality interface on fewer vertices remains separating after adding arbitrary non-port vertices.

## Search method

`tools/semantic_cegis_portfree.py` runs an exact master/oracle CEGIS loop.

The master selects four non-port vertices. Every known A/B fooling pair induces a difference graph on the non-port vertices; the selected four-set must contain at least one edge of every such difference graph. Equivalently, it may not be an independent four-set in any accumulated difference graph.

The oracle asks for an `A` coloring and a `B` coloring with the same complete equality pattern on the proposed four-set. SAT produces another sound fooling-pair cut. UNSAT produces a genuine semantic-interface candidate. If the master itself becomes UNSAT, all port-free equality interfaces of support at most four are excluded.

## Reliability and timeouts

The workflow uses a pinned upstream commit, validates every seed coloring, writes checkpoints atomically, and treats timeout/UNKNOWN states as **non-results**. A timeout is never converted into SAT or UNSAT evidence.

Run 2 showed why the guard is necessary: one solver call remained active for several minutes after the last completed CEGIS iteration. The outer timeout safely stopped it without losing the previous checkpoint. Before another large continuation run, the preferred engineering improvement is a sound per-query interruption/UNKNOWN path or a specialized fast four-set candidate generator, while retaining exact SAT for certificate-producing decisions.
